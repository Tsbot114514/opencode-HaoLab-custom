# HaoLab OpenCode 1.15.20

## 修复

- 默认单次模型请求的整体时长上限改为 20 分钟；响应头等待与 SSE 流停顿分别保留独立的 5 分钟保护，可通过 `timeout`、`headerTimeout`、`chunkTimeout` 配置覆盖或关闭。
- 修复空内容和开始事件重置重试预算的问题；仅收到非空思考、正文、工具参数或完整工具调用后重置连续失败计数，避免无实质进展的无限重试。
- 修复大型工作区备份时，一次展开大量消息或工具记录导致“Maximum call stack size exceeded”的问题，改为在一致性数据库事务中逐条读取并暂存记录。
- 修复会话记录总量超过 64 MiB 时无法导出、预览或生成覆盖前恢复包的问题。采用分块迁移包格式 v2：小型清单保存项目身份、时间及分块索引，会话记录按约 8 MiB 的 JSONL 数据块保存，不再把完整历史塞入一个 JSON 清单。
- 导出、预览、确认载入及覆盖前恢复包统一使用分块处理。预览使用临时索引数据库校验记录，恢复逐条写入，避免将完整消息历史同时载入内存。
- 修复 Windows 下来源会话路径大小写不一致时，已包含的附件路径未正确重绑到本机的问题。

## 保留与校验

- 继续备份项目工作文件、会话数据库记录、对应的 `sessions/<sessionID>/` 文件夹及会话差异记录；不删减对话、不截断工具输出。原有依赖和缓存排除规则仍适用。
- 每个记录块保存字节数、记录数和 SHA-256；载入前检查 ZIP CRC、分块清单、记录类型、重复键及关联归属。损坏、缺失、重复或超限记录块会被拒绝。
- 保留时间对比、明确覆盖确认、内容变化检测、覆盖前恢复包、普通失败回滚及客户端会话缓存刷新。

## 使用说明

- 仅支持新分块格式 v2，不读取旧格式迁移包。请在源设备使用 1.15.20 或支持 v2 的新版应用重新导出，并在目标设备使用支持该格式的版本载入。
- 常规记录块约 8 MiB；单条编码后记录上限 64 MiB，超过时明确报错而不是截断。迁移包解压后总量上限仍为 10 GiB，普通单文件上限 1 GiB，ZIP 条目上限 100,000。
- 导出需要记录暂存空间，预览和载入需要解压校验及临时索引空间，覆盖还会保留恢复包。请在相关磁盘预留足够可用空间，并停止目标工作区的 agent、文件编辑和数据库写入。
- 当前仍限相同操作系统；不包含 Git 历史、依赖缓存、撤销快照、目录外附件和外部数据库。迁移包与恢复包未加密，请妥善保管。

## 测试

- 使用超过 64 MiB 的关系记录和 200,124 条消息片段验证导出、预览、恢复、覆盖及恢复包再次载入，核对记录数量、内容摘要和会话本地文件字节。
- 使用 200,123 条事件记录验证预览后的内容变化检测，并覆盖 Unicode 分块边界、大单条记录、损坏或缺失分块、重复键和旧格式拒绝。
- 在 Bun 和 Node v24 运行时验证大型数据迁移流程，避免仅在开发测试环境通过而在桌面 sidecar 中失败。
